# Engineering decisions and evolution

These accepted decisions use the original ADR IDs for traceability. The alternatives compare designs with the current constraints. The dated evidence below distinguishes the earlier implementation from the final deployment.

| ID and problem | Accepted design | Alternatives and consequences |
|---|---|---|
| **ADR-001 · Analytical database and isolation** | Use ClickHouse for analytical scans. Put batch and CDC in distinct databases. Use the local ClickHouse admin for both publishers and the Grafana datasources. | PostgreSQL-only serving would share transactional staging resources with analytical work. Two ClickHouse servers would improve isolation but add local deployment overhead. One server keeps separate publication contracts while sharing resources and outages. The local learning deployment grants administrative access to its datasource credential. |
| **ADR-002 · Stable analytical grain** | Publish nine dimensions and three facts with exact application, offering and enrollment-attempt grains. Keep whole snapshots by `snapshot_id` and use stable HMAC keys for student and applicant identities. | Serving normalized source data would leave each dashboard to reconstruct business joins. Row-level Type 2 dimensions would capture separate change histories but would complicate the current full-snapshot contract. |
| **ADR-003 · Freshness and independent verification** | Retain run-pinned batch and independent CDC. Airflow manages finite extracts and warehouse tasks. PostgreSQL preserves typed batch input so Spark can retry from one accepted run. Reconcile published same-grain counts and record both boundaries. | CDC-only would lose a separately sourced full-run comparison and the batch dimensional history. Batch-only would require frequent full extracts for freshness. Writing CDC to PostgreSQL and ClickHouse creates two sink outcomes to recover and verify. The current stream writes directly to ClickHouse. |
| **ADR-004 · Local deployment** | Use single-host Docker Compose with persisted data, profiles and pinned runtime versions. | Host installs are harder to reproduce. Distributed orchestration introduces significant local complexity. This design provides a reproducible workstation deployment. Broker, database and disk availability still depend on one host. |
| **ADR-005 · External SQL Server access** | Use Microsoft ODBC Driver 18 and `pyodbc` for batch and the Debezium driver for CDC. Endpoint, credentials and TLS are configured through environment variables and reviewed with the source owner. | A bundled database would not represent the assessed external source. Hard-coded connection values would couple code to one environment. Reachability, permissions, certificate validity and retention require site-specific checks. |
| **ADR-006 · Capture of changes** | Use SQL Server CDC and the Debezium connector on Kafka Connect. Persist its log lineage, offsets and schema history in Kafka. | Timestamp polling can miss deletes and previous versions. Direct sink coupling would remove a durable replay log. The broker and source both need retention policies and a checked initial baseline. |
| **ADR-007 · Streaming processor** | Use a separate Spark Structured Streaming worker with a persistent checkpoint, validated Kafka identity and verified `foreachBatch` writes. | An Airflow DAG suits finite work. Polling with repeated batch jobs leaves progress and recovery to custom code. Spark supplies a Kafka progress model and a place to apply schema and identity checks. The ClickHouse sink still needs its own seal and replay validation. |
| **ADR-008 · Serving visibility and current state** | Publish batch through a final snapshot marker and CDC through verified batch seals and generation activation. Project current rows using source ordering and exclude winning deletes. Grafana reads CDC aggregate and health views for low-latency reporting. | In-place mutations or waiting on background merges would couple visibility to asynchronous storage behavior. Combining both paths into one upserted fact layer would need shared ordering and delete semantics. The serving views keep published contracts predictable and add query-time grouping cost. |

Read the linked [architecture](overview.md), [warehouse](../05-data-platform/warehouse.md) and [operations](../07-operations/runbook.md) for mechanics and failure handling.

## Evolution and verified engineering issues

| Evidence | What changed |
|---|---|
| `1396859` and the documentation history through `76d9ed0` | The project established typed staging, dimensional facts, Airflow orchestration and batch reporting. Historical screenshots and docs show the former Airflow CDC consumer and shared CDC/staging components. |
| `0f885e0` and the 21 November validation record at `55843c3:docs/assets/validation-2026-11-21.md` | The warehouse gained a guard against republishing an already successful source run. The legacy stream had consumed its initial cut, but that record did not establish active generation or controlled post-snapshot changes. |
| `6d81675` | The extract DAG gained a validated run-ID handoff, the Spark loader pinned input by run, and the separate ClickHouse CDC database and commit ledger replaced the PostgreSQL CDC write path. The former Airflow CDC consumer code was removed. [Current source](../../airflow/dags) |
| [22 November cutover](../06-observability-and-quality/testing-and-validation.md#live-cdc-cutover) | A ClickHouse restart during verification interrupted bootstrap validation. Spark resumed the saved checkpoint. Bounded query settings reduced the final verification workload, and the generation became active. The checkpoint mount permissions and persistent Grafana datasource name/UID also matter on an upgraded host. |

The batch preflight checks Java and Spark before submitting the job. Run-pinned integration fixtures, SQL publication assertions, fault-injected streaming replay and datasource checks cover the resulting design. The [acceptance status](../06-observability-and-quality/testing-and-validation.md) records which steps used an external source and which used fixtures.
